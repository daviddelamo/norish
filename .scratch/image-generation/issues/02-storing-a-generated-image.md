# 02 — Storing a Generated Image

Status: resolved
Blocked by: None — can start immediately

Spec: `.scratch/image-generation/spec.md`

## What to build

Norish can store a Generated Image: a picture of a dish that AI drew, cropped to exactly 1280×720, written into the recipe's gallery as its primary image and replacing whatever held that slot. Nothing generates one yet — this ticket makes the destination exist and proves it behaves.

## Notes

**Read ADR-0025 before starting.** This write is deliberately destructive, and three safer-looking alternatives were considered and rejected. Do not soften it.

The replacement operation is the only place a Generated Image is written. It deletes the row that held order 0 along with its file, writes the new image at order 0 with the marker set, and leaves every other row's contents and relative order untouched. A recipe holds at most one Generated Image, so a second run replaces its own predecessor rather than accumulating toward the ten-image cap.

The save path gains a cover-crop variant. The existing recipe-image save fits an upload inside 1280×720 without cropping and must keep doing exactly that; only generated bytes are cropped.

The marker is a column on the recipe images table, carried in the recipe DTO. Nothing renders it — no badge, on any surface. That is a decision, not an omission.

Dish Colour recomputation belongs to the worker in ticket 05, not to this operation.

## Acceptance criteria

- [ ] A migration adds the generated marker to recipe images; existing rows are unmarked.
- [ ] The marker is carried in the recipe DTO.
- [ ] One repository operation writes a Generated Image at order 0 and deletes the row that held order 0, together with its file.
- [ ] Every other gallery row keeps its contents and its relative order.
- [ ] A second generation replaces its own predecessor; a recipe never holds two Generated Images.
- [ ] A recipe with no images ends with exactly one, at order 0.
- [ ] Generated bytes are stored at exactly 1280×720, from a landscape source and from a square source.
- [ ] Uploaded images are unaffected: they still fit inside 1280×720 without cropping.
- [ ] Existing size and format validation still rejects what it rejected before.
- [ ] Covered by a real-database test beside the existing recipe dish-colour database test.
