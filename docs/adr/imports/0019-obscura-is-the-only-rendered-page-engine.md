# Obscura is the only rendered-page engine

URL import renders a page before parsing it, because plenty of recipe sites build the recipe with JavaScript. That rendering used to be an unpinned third-party Chromium image (`zenika/alpine-chrome:latest`) driven by Rebrowser's patched Playwright fork, and Norish carried a layer of its own on top: it discovered Chrome's debugger socket through `/json/version`, re-resolved the hostname to an IP because Chrome rejects the Host header otherwise, fabricated a Windows Chrome 131 fingerprint with matching client hints, invented a referer by coin flip, watched for Cloudflare's "Just a moment" markup, and then raced three recipe-shaped selectors. Two of those responsibilities are the browser's, one is the parser's, and the fingerprint actively fought the browser it was attached to — a hard-coded Chrome 131 identity in front of whatever Chromium `:latest` happened to be that week is a contradiction a bot check can read. **Rendering is now one Norish-built Obscura sidecar, reached over CDP with official `playwright-core`.** The image is built from a pinned upstream commit with `--features render,stealth` and starts `serve --stealth` as its entrypoint, so stealth is a property of the artifact rather than of how an operator starts it; `OBSCURA_ENDPOINT` replaces `CHROME_WS_ENDPOINT` outright, with no alias; and the fetch itself is now obtain the shared connection, open an isolated context, inject only the requesting user's Site Auth Tokens, navigate once under one deadline, return the HTML, close the context. We rejected pulling upstream's `h4ckf0r0day/obscura` image (its Dockerfile compiles `render` only, so `--stealth` is accepted while the stealth transport was never built in — half a feature, silently), keeping Chrome as a fallback engine or a per-site policy (two engines means two fingerprints, two failure modes, and an operator problem the server would hide by quietly switching), and keeping any Norish-authored evasion beside Obscura's (one coherent identity beats two disagreeing ones).

## Consequences

- Norish owns its browser artifact. `docker/obscura/` builds it, `pin.env` records the upstream revision and the immutable tag together, and `verify-pin.sh` — run by both release workflows — refuses to tag a release whose Compose examples name a tag that is not published as a multi-architecture manifest. Upgrading Obscura is an explicit change to that pin, never a `docker compose pull`.
- Building rather than pulling costs a from-source Rust compile of a browser engine on two native runners. That is why it is its own workflow on its own cadence (`obscura-image.yml`), not a step in every application release.
- Stealth is not configurable, and neither is anything else about the browser: no plain mode, no proxy, no fingerprint profile, no tracker-blocklist exceptions, no worker count. Obscura's tracker blocking is accepted wholesale as part of the trade — a site that breaks because a blocked domain was load-bearing has no per-site escape hatch here, by design.
- `--allow-private-network` and `OBSCURA_ALLOW_PRIVATE_NETWORK` appear nowhere: not in the image, the Compose files, the tests, the examples, or the docs. Obscura's default deny of loopback, RFC1918 and link-local — enforced at DNS resolution, so a public hostname resolving inward is still refused — is the only thing standing between an authenticated URL import and the deployment's internal network. Reintroducing that flag is a decision to reopen this ADR.
- A failed render fails the import. `fetchViaPlaywright` returns empty, the import path reports its usual fetch failure, and nothing retries against another engine or an undocumented HTTP client. An operator with a broken `obscura` service sees broken imports, which is the honest signal; the server still starts, because instances that never import by URL should not be held hostage to it.
- The boundary is narrow on purpose and stays that way. `packages/api/src/playwright.ts` holds one cached connection, replaced on the next call once Obscura drops it; `parser/fetch.ts` holds the per-fetch context. Whether returned HTML contains a recipe remains the parser's and the AI fallback's question — the fetch layer must never grow a selector wait again. There is no engine registry, no `BrowserEngine` interface, and no second implementation to justify one.
- Runtime `playwright-core` tracks `@playwright/test` (1.61.x) so the repository carries one Playwright generation. The web E2E runner and its Chromium download are untouched and unrelated: that is browser *acceptance tooling*, not a production dependency, and this decision deliberately does not entangle the two.
- Obscura is an implementation concept, so it stays out of `CONTEXT.md`. Operators meet it as a service name and one setting; the product language around imports is unchanged.
